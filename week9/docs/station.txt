1. The broker routes messages between publishers and subscribers by topic, decoupling them so the node never needs the Pi's IP address.
2. Your station uses three ID-specific topics (e.g., `bench/sXX/light`, `bench/sXX/status`, and `bench/sXX/config`), and `bench/+/light` matches the light topic for *all* stations whereas `bench/s07/light` only matches station 07.
3. `sudo ufw allow 1883` opens the default MQTT port on the Pi's firewall, which otherwise blocks unsolicited incoming traffic from external nodes.
4. QoS 0 sends messages without acknowledgment while QoS 1 guarantees delivery with retries; telemetry uses QoS 0 because continuous readings are quickly replaced, avoiding unnecessary overhead.
5. `config.py` is git-ignored to keep private credentials like Wi-Fi passwords out of the repository, while `config_example.py` is committed with safe placeholders as a setup template.
